# Как устроен код

Короткий путеводитель для разработчика: где что лежит, как части общаются между собой
и как сделать типовые изменения.

## Карта папок

```
src/
├─ main.ts                 точка входа: создаёт Game
├─ config.ts               ВСЕ настраиваемые числа (сложность, физика, очки, звук)
│
├─ core/                   каркас приложения
│  ├─ Game.ts              сервисы, игровой цикл, переключение сцен
│  ├─ Scene.ts             интерфейс «экрана»
│  └─ Input.ts             клавиши/мышь/тач → команды (здесь меняется управление)
│
├─ scenes/                 экраны игры (по одному классу на экран)
│  ├─ MenuScene.ts         меню: режим, сложность, треки, громкость
│  ├─ LoadingScene.ts      загрузка и анализ трека
│  ├─ PlayScene.ts         сама игра: забег, пауза, смерть в хардкоре, финиш
│  ├─ ResultsScene.ts      итоги песни
│  └─ play/
│     ├─ hud.ts            всё, что рисуется поверх игры: волна, очки, комбо, пауза
│     └─ feedback.ts       таблица «событие забега → эффект и звук»
│
├─ rhythm/                 логика уровня — без графики и звука
│  ├─ types.ts             типы: пол, яма, шипы, кольцо, Chart (готовый уровень)
│  ├─ geometry.ts          размеры героя и препятствий
│  ├─ Run.ts               физика забега, столкновения, ошибки → события
│  ├─ Scorer.ts            оценки PERFECT/GREAT/GOOD, очки, комбо, ранг
│  └─ generator/           построение уровня из музыки
│     ├─ buildChart.ts     «дирижёр»: идёт по битам и вызывает паттерны
│     ├─ ChartBuilder.ts   «стройплощадка»: пол, ямы, списки объектов, темп
│     └─ patterns.ts       препятствия (по объекту на каждое)
│
├─ audio/
│  ├─ analyze.ts           анализ трека: темп, биты, бочка, громкость
│  ├─ fft.ts               быстрое преобразование Фурье
│  ├─ AudioEngine.ts       воспроизведение, часы песни, громкость, спектр
│  └─ sfx.ts               синтезированные звуки (таблица SOUNDS)
│
├─ render/                 графика мира
│  ├─ Renderer.ts          собирает кадр из слоёв
│  ├─ Camera.ts            масштаб, камера, перевод мир → экран
│  ├─ MusicPulse.ts        сигналы «в такт»: доля, бочка, спектр
│  ├─ Effects.ts           частицы, всплывающие слова, вспышки
│  ├─ particles.ts         система частиц
│  ├─ palette.ts           цвета (палитра у каждой песни своя)
│  └─ layers/
│     ├─ Background.ts     небо, солнце, город-эквалайзер
│     ├─ world.ts          пол, препятствия, кольца, подсказки
│     └─ hero.ts           герой и его шлейф
│
├─ ui/
│  ├─ Ui.ts                виджеты на canvas: текст, панель, кнопка, ползунок
│  └─ widgets.ts           общие куски: логотип, кнопки звука/паузы, громкость
│
└─ data/
   ├─ playlist.ts          треки из папки playlist/
   ├─ library.ts           список треков + загрузка/анализ с кэшем
   ├─ records.ts           рекорды игрока
   ├─ settings.ts          выбранные режим, сложность, трек
   └─ storage.ts           безопасная обёртка над localStorage
```

Правило зависимостей: `rhythm/` и `audio/analyze.ts` не знают ни про графику, ни про DOM.
Поэтому уровень можно построить и прогнать в симуляции без браузерного окна.

## Как всё крутится

```
Input ──команды──► Game ──► текущая Scene
                     │          │  update(dt)   — логика экрана
                     │          │  view()       — что показать в мире
                     │          │  drawUi(ui)   — интерфейс поверх
                     ▼          ▼
                 Renderer ◄── WorldView { run, chart, songT }
```

Каждый кадр `Game.frame()` делает одно и то же:
1. `scene.update(dt)` — сцена двигает свою логику;
2. `renderer.update()` и `renderer.draw(scene.view())` — рисуется мир;
3. `ui.begin()` → `scene.drawUi(ui)` — рисуется интерфейс, кнопки регистрируют свои зоны клика.

Переход между экранами — `game.go(new SomeScene(...))`, плюс готовые `game.toMenu()` и `game.play(track)`.

**Путь песни:** `MenuScene` → `game.play(track)` → `LoadingScene` (загрузка и анализ, есть кэш)
→ `PlayScene` (строит уровень `buildChart` и создаёт `Run`) → `ResultsScene`.
В хардкоре после смерти `PlayScene` снова вызывает `game.play(track, { attempts + 1 })`.

**Синхронизация с музыкой.** Время игры — это время песни: `audio.songTime()`.
Нажатия запоминаются с этим временем и передаются в `run.update(songT, presses)`.
Физика считается мелкими шагами по 1/240 с, так что тайминг не зависит от FPS.

## Паттерны в коде

| Паттерн | Где | Зачем |
| --- | --- | --- |
| State | `core/Scene.ts`, `scenes/*` | каждый экран — отдельный класс с одинаковым интерфейсом |
| Strategy | `rhythm/generator/patterns.ts` | каждое препятствие — объект с методом `place` |
| Builder | `rhythm/generator/ChartBuilder.ts` | уровень собирается по шагам, `build()` отдаёт готовый `Chart` |
| Observer + таблица | `Run.events` → `scenes/play/feedback.ts` | физика сообщает, что случилось; реакции описаны таблицей |
| Command | `core/Input.ts` | клавиши превращаются в команды, сцены не знают про клавиши |
| Immediate-mode UI | `ui/Ui.ts` | кнопка рисуется и сразу становится кликабельной, нет отдельного дерева виджетов |

## Рецепты

### Поменять сложность, физику, очки
Только `src/config.ts`. У каждого числа есть комментарий.

### Добавить новое препятствие
1. В `rhythm/types.ts` опиши его тип (например, `Laser { x; y; ... }`) и добавь массив в `Chart`.
2. В `ChartBuilder.ts` добавь такой же массив и верни его в `build()`.
3. В `patterns.ts` напиши паттерн:
   ```ts
   export const LaserJump: JumpPattern = {
     name: 'Лазер',
     place(b, beat, { r, ts }) {
       if (r > 0.2) return null;              // не подходит — пусть попробует следующий
       b.lasers.push({ x: b.X(ts + b.airT / 2), y: b.curY + 40 });
       return ts + b.airT;                     // когда герой приземлится
     },
   };
   ```
   и поставь его в `JUMP_PATTERNS` (они пробуются по порядку, первый подошедший побеждает).
4. В `Run.ts` добавь проверку столкновения (по образцу `checkHazards`).
5. В `render/layers/world.ts` добавь функцию рисования и вызови её из `drawLevel`.

Паттерны для «тихих» долей — `QUIET_PATTERNS`, для дропов — `ACCENT_PATTERNS`.

### Добавить экран
Создай класс в `scenes/`, реализующий `Scene` (`update`, `view`, `drawUi`, `onCommand`),
и переходи на него через `game.go(new MyScene(game))`. Пример простого экрана — `LoadingScene.ts`.

### Поменять управление
`KEY_MAP` в `core/Input.ts`. Например, `ArrowUp: 'primary'` сделает прыжок и на стрелку вверх
(но тогда в меню стрелка вверх перестанет листать треки).

### Добавить звук
Добавь имя в `SoundName` и рецепт в `SOUNDS` (`audio/sfx.ts`), затем вызывай `audio.sound('имя')`.

### Изменить реакцию на событие (вспышка, частицы, звук)
`scenes/play/feedback.ts` — одна функция на каждый тип события.

### Добавить кнопку в интерфейс
В `drawUi` любой сцены:
```ts
ui.button({ x, y, w: 200, h: 44 }, 'Текст', () => сделатьЧтоТо(), { primary: true });
```

## Отладка

- `?autoplay` в адресе — игра проходит трек сама и жмёт ровно в бит.
- В режиме `npm run dev` в консоли браузера доступен `dbg` (`dbg.buildChart`, `dbg.Run`,
  `dbg.analyze`, `dbg.game`). Например, можно построить уровень и прогнать его без звука:
  ```js
  const t = dbg.game.library.tracks[0];
  const buf = await dbg.game.audio.decode(await (await fetch(t.url)).arrayBuffer());
  const chart = dbg.buildChart(await dbg.analyze(buf), 1, 1, 'hardcore');
  ```
